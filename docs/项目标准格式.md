# 项目标准格式

本文件描述 Live2D Studio 的实际目录组织与分层约定。新增文件、模块时应保持与本文一致；README 中的「项目结构」一节是面向使用者的简要版本。

## 分层约定

- 入口唯一：根目录 `main.go`，不承载业务逻辑。
- 模块内部固定三层：
  - `module.go`：实现 `router.Module`，注册路由并声明依赖。
  - `handler.go`：参数绑定、调用 service、返回统一响应。
  - `service.go`：业务逻辑，直接操作 Gorm 模型；本项目为单用户桌面场景，不设 repository 层。
- 模块之间通过 service 结构体组合，由 `internal/bootstrap` 统一注入；不要在模块内直接打开数据库连接。
- 跨模块共享的数据结构放在 `internal/model`；仅模块内部使用的类型留在模块目录。
- 前端按 `api / store / hooks / components / pages` 分层：页面只做组合，网络请求收敛在 `api/`，跨页面状态收敛在 `store/`。
- 页面统一使用 `src/pages/{页面}/index.tsx` 目录形式（如 `pages/characters/index.tsx`），页面私有子组件与样式可放在同目录下。
- `src/components/` 按功能域分目录：`stage/`、`canvas/`、`camera/`、`character/`、`speech/`、`chat/`、`live/`、`coding/`、`settings/`、`common/`；`ui/` 只放 shadcn 基础组件。新增组件归入对应功能目录，不要堆在 components 根目录。

## 命名与注释

- Go 文件按职责命名（`service.go`、`handler.go`、`module.go`），导出符号必须有以符号名开头的中文注释。
- 每个包在主要文件顶部写包注释；其他文件用一行文件职责注释。
- 前端每个 `.ts/.tsx` 文件顶部写块注释说明职责；组件 Props、导出的 Hook 与工具函数使用 JSDoc。
- 关键并发、流式、安全校验与边界处理必须有解释“为什么”的注释，避免逐行复述代码。

## 新增业务模块的步骤

1. 在 `internal/modules/<name>/` 下创建 `module.go`、`handler.go`、`service.go`。
2. 需要持久化的数据结构放入 `internal/model/`，并加入 `internal/migrate` 的 `AutoMigrate` 列表。
3. 在 `internal/bootstrap/app.go` 中构造 service 实例，并传给 `router.Register`。
4. 在 `server/docs/openapi.yaml` 补充接口定义，在 `internal/tests/` 增加集成测试。
5. 前端在 `src/api/` 增加请求函数、`src/types/api.ts` 增加类型，再接入页面。
