# 当前实现与扩展方向

本版本按需求采用 Wails 3、Go / Gin 和 React，并根据补充要求使用 Eino 实现智能体。参考 Python 项目仅作为功能与资源参考，不作为运行时依赖。

## 已实现的核心流程

1. 用户选择 Live2D 角色，人设保存到 SQLite。
2. 文本、语音识别结果、图片附件通过 Gin HTTP 接口进入会话服务。
3. 会话服务加载对应角色的人设和最近历史。智能体将该角色最近更新的长期记忆加入上下文。
4. agentcore 的 ADK 构建器按角色人设创建智能体，以 OpenAI 兼容流式模型生成回复；开启工具时由 ADK 编排模型与工具往返，并提供角色表情、计算、时区查询、长期记忆搜索、显式记忆保存，以及当前角色名称 / 介绍 / 人设的持久化修改。
5. SSE 将文本增量、表情、保存后的角色资料和工具执行状态传给 React。回复、生成状态和工具执行状态一并保存。
6. 系统或 API 语音朗读回复，并驱动 Live2D 嘴型动画。

模型上下文优先使用近期完整对话轮次，受设置中的历史消息数量限制。历史文字合计最多 128,000 字节，单条最多 64,000 字节，历史图片的编码大小合计约 10.7 MiB。助手会收到相应的省略标记。当前输入和已保存的对话记录保持完整。

模型配置的 `provider` 支持 `openai`、`deepseek`、`ollama`、`lmstudio`；旧版单份配置会识别服务类型并保留，无法识别的兼容地址归入 `openai`。`GET /settings/llm/:provider` 读取各服务独立存档（地址、模型、参数、工具开关、密钥存在标志），仅无存档时回退到后端初始值；保存后才切换当前服务。密钥留空只保留该服务的密钥。前端切换时取消旧请求，读取失败阻止保存，未保存编辑按服务保留于页面内。

`ollama` 使用本地服务地址，无需配置 API Key。模型发现接口 `POST /settings/ollama/models` 接受未保存的服务地址，经原生 `/api/tags` 返回模型名称、规模、量化方式和大小，8 秒超时、2MiB 响应上限，不修改配置。Ollama 地址支持根路径、`/api`、`/v1` 和反向代理前缀；生成时统一适配至兼容接口，继续经过 agentcore，并使用固定占位凭据避免转发已保存的云端密钥。本地连接测试为冷启动预留 120 秒。

`update_character` 绑定当前对话的角色 ID；模型仅可提交 `name`、`description`、`system_prompt` 的可选修改，无法选择其它角色或改动模型路径。字段先统一校验，再在事务中更新；失败不发送角色更新事件，成功后通过 SSE `character` 事件同步前端。每轮生成重新读取角色，系统消息包含最新名称、介绍和人设。工具调用需由用户明确要求触发。

初始 Mao / Shizuku 资源位于后端 character 模块的 `assets/` 中，启动时通过与上传 ZIP 共用的 `importArchive` 校验 / 导入流程落盘至 `<data_dir>/models/<资源 UUID>/`。旧角色只更新 `model_path`，角色主键、人设、命名、会话与记忆保持不变；模型路径已迁移时跳过导入，前端无需携带模型文件。

`get_character_actions` 从后端模型存储目录读取真实 `model3.json`，校验资源文件存在并限制引用不能越出该角色目录。`play_motion` 与 `set_model_expression` 根据实时列表校验 ID 后发送 `stage_action`；动作 ID 采用 `[组名, 索引]`，支持空组名和不同 JSON 转义。工作台 / 桌宠核对角色与模型路径，再调用 Live2D 舞台句柄并显示实际执行结果。工具返回仅代表请求发送，不能作为成功播放的证明；不可读清单、合法空列表与缺失资源计数分别处理。

角色的 `action_names` JSON 列按 `motions`、`expressions`、`moods` 保存自定义名称，GET 动作接口同时返回 `label` 和 `default_label`。PUT `/characters/:id/action-names` 按模型路径与稳定 ID 校验后仅更新命名列，空名称恢复默认，最多 60 个字符；名称保存不会覆盖并发人设修改。入口位于角色管理的各角色卡片，命名弹窗支持搜索、原始名称对照、独立模型预览与恢复默认，编辑不会切换聊天伙伴或改变聊天情绪 / 缩放。弹窗预览期间暂停卡片中的模型实例。工作台保留播放控制，舞台和智能体都使用已保存名称。

没有服务商密钥时，应用不会伪造模型回复。本地兼容服务可不提供密钥。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| bootstrap | 数据库、迁移、模块装配、静态资源与 HTTP 生命周期 |
| agent | agentcore ADK 智能体、模型适配、工具循环和错误脱敏 |
| character | 人设与 Cubism 模型导入 |
| conversation | 会话、消息、上下文、并发约束、流式响应和持久化 |
| memory | 角色记忆的本地存储、管理与关键词检索 |
| settings | 本地设置、输入校验、密钥保留及环境覆盖 |
| speech | 兼容 ASR / TTS 接口代理 |
| desktop | Gin 到 Wails 窗口控制的接口适配 |
| sceneassets | 图片 / 视频上传、素材库、删除、本地媒体文件及 Range 输出 |

## 工作台管理

工作台可切换对话与舞台设置。对话记录支持按标题或角色搜索，窄窗口从顶部打开对话记录。表情和动作集中在同一页签，背景支持图片 / GIF / 视频 / HTML 导入，素材在 SQLite 登记并保存到本地 `scene-media`。HTML 源码以纯文本提供，仅在舞台的沙箱内渲染，不执行脚本或加载外部资源。氛围特效与自定义图片 / 视频叠加层可以组合，支持强度和正常 / 滤色 / 变亮混合。

自由画布层支持标题与自定义 HTML / CSS 组件，提供拖动、缩放、键盘微调、层级、显隐、锁定、复制与删除撤销。共享计数支持手动增减与按时间自动累加，组件通过变量绑定多个计数数据。布局和计数独立存储在 Zustand 的 `live2d-studio-canvas` 本地持久化项；展示时钟不写存储，也不触发 Live2D 重建。HTML 在禁止脚本的 iframe 内渲染，计数更新直接修改绑定文本与属性，保留 CSS 动画。当前计数未接外部接口或直播平台。

画布支持自适应及六种固定比例，由 `useStageFrame` 观察外层空间并等比容纳舞台；小画布同步缩放标题、HTML 和组件边距。比例与操作按钮显隐存入舞台偏好，隐藏按钮时保留外部恢复入口与 H 快捷键，隐藏不会改变布局位置。舞台模板由 `stageTemplates` 仓库独立存入 `live2d-studio-stage-templates`，包含舞台外观、组件及共享计数快照，最多 20 个；先成功写入存储再更新模板列表，容量不足时保留原模板并提示失败。自动计数保存为当时的值，应用后重置起始时间；应用和删除提供单步撤销，缺失素材跳过并提示。

Wails 页面保留原生运行时，业务请求及媒体直接使用实际 Gin 回环地址，避免 Windows WebView 资源代理缓冲 SSE 和大视频。GPT-5 / o 系列自动省略不兼容的 temperature 并使用对应 token 参数；连接测试使用实际 Eino 流式调用。失败原因脱敏后随消息保存。

## 与原项目相比尚未覆盖

原项目提供了大量后端与扩展，当前没有逐个移植以下高级能力：

- 内嵌本地 ASR / TTS / VAD 推理，自动语音活动检测、免按键连续对话、低延迟逐句语音队列。
- 摄像头与屏幕实时采集、直播弹幕接入、群组聊天、主动发言。
- MCP 工具发现与配置、向量检索、自动提炼记忆、翻译、原生 Claude / Gemini 等非兼容协议。
- 桌宠鼠标穿透、托盘恢复、全局快捷键与安装程序。当前桌宠支持透明置顶与拖动。
- 原项目 WebSocket 协议兼容层；本项目采用 Gin REST + SSE。

本地模型目前通过兼容 HTTP 服务接入，不会启动 Python 子进程。后续若要将推理直接嵌入 Go，应独立增加引擎适配器；不要将推理逻辑写入 Gin handler。
